# Audit of the implementation (2026-11-11)

The owner asked for an audit of the driver. Three independent reads of all of our own code, then
each finding acted on was checked in the source (and on VM 210 where it could be run):

- the kernel extension: `kext/virtiogpu/` and `include/ripple_gpu_uapi.h`;
- the winsys and the GL bundle: `winsys/virgl/ripple/`, `targets/ripple-gl/`,
  `frontends/cgl/cgl_device.c`, `gldriver/ga/`, the libatomic fallback, the Mesa patches;
- the CGL frontend: `frontends/cgl/` (entry points, takeover, contexts, drawables, the
  dispatch generator).

Verdict: no memory-safety hole in the paths ordinary programs take, and the virtqueue, the
buffer table, the uapi structures and the dispatch marshalling read as sound. The real
weaknesses were at the edges: what a hostile or crashed client can do to the kernel side, what
happens after a host stall, GL contexts used from more than one thread, and how GL frames reach
windows. The last one was behind all three glitches the owner reported the same day.

"Fixed" names the commit. "Open" items are not known to bite today; the open one marked **high**
should be done before games that render from a second thread are tried.

## Kernel extension

| Finding | Severity | State |
|---|---|---|
| `DISPLAY`'s rectangle went to the host unchecked; QEMU aborts on a size it can't allocate, so any process could end the VM | crash | fixed 3436c76 (must lie on the screen; `gpu-stress` checks) |
| Surface client kept its task without a reference and used it later | memory corruption (hostile client) | fixed 3436c76 |
| Surface client returned up to 4 KB of stale kernel memory from every selector (no dispatch table, sizes never set) | information leak | fixed 3436c76 (`gpu-stress` checks) |
| A thread waiting for a free command slot was not woken when a timed-out slot completed, and nobody drained for it without the interrupt | hang after a host stall | fixed 3436c76 |
| After detach and unref both went unanswered, the buffer's pages were freed while the host could still write to them | memory corruption after a host stall | fixed 3436c76 (the pages stay wired) |
| A `DISPLAY` whose flush failed switched the scanout without being recorded; destroying that buffer then froze the screen | wrong output | fixed 3436c76 |
| Showing a second buffer went through the console frame (a full upload and a flash); a new rectangle for the shown buffer was not sent | cost, minor | fixed 3436c76 |
| Shapes over 4 KB (about 510 rectangles) always failed | minor | fixed 3436c76 (up to 64 KB) |
| Mode setup leaked the host resource on its error path; rings freed before the interrupt source was removed | minor | fixed 3436c76 |
| A timed-out `SUBMIT`'s command buffer is reused by the next one | wrong output after a host stall | open |
| Fence numbers pass 2^32 after about 50 days at 1000 commands/s; QEMU's virgl path compares 32 bits, and commands then never complete (Linux guests share this) | hang, far off | open |
| Buffers over 64 MB can fail to attach when guest memory is fragmented (QEMU allows 16384 entries); the doc says 256 MB | clean error | open |
| Client backing is wrapped again only when address or length change; a new allocation at the same address would keep showing the old pages | wrong output, unverified | open |
| `refresh()` ignores failed transfers; cursor queue overwrites its slot before the add is known to work | minor | open |
| No cap on the memory one client can pin (65536 buffers of 256 MB, any surface size) | hang by a hostile client | open |
| `WAIT` treats its timeout as zero or non-zero | minor (documented) | open |
| 32-bit processes can't lock a surface (their structure is smaller); nothing does so today | minor | open |

## CGL frontend

| Finding | Severity | State |
|---|---|---|

| Client-storage records outlive a texture re-specified another way, and a destroyed context's textures | wrong output, slots fill | open |

## Outside the driver, found on the way

- The guest panics when it goes to sleep, and `configd` crashes at every boot
  ([known-issues](../known-issues.md)).
- `scripts/stop.sh` exited silently when the guest had no address (fixed, f29a548).
- The debug log grew by 100 MB a night in WindowServer (fixed, cedf744).
- `docs/kext-uapi.md` lacked `SURFACE_INFO` and the framebuffer mapping (fixed, f29a548).
- `CGSGetSurfaceOpacity` in 10.6.8 fails for every non-NULL pointer (an inverted check), so
  the driver watches the setter instead (`gld_opacity.c`).
